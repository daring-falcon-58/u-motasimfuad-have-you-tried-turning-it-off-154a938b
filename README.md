## Entry line (106 chars / 106 bytes, 1 line, UTF-8, no trailing newline)

## Methodology (what the judge compares, and how this line was chosen)

The brief (competition.yaml + RULES.txt, read in full before writing
anything) fixes the prompt — *a single funny line, under 200
characters, that a hopeless tech support agent says to a desperate
customer* — and the judge (z-ai/glm-5.3-flash, pairwise, margin 1–5,
each pair judged in both orders, 3 Swiss rounds + top-12 playoff).
Its five criteria, in the brief's own order:

1. Is a funny single-line reply from a hopeless tech support agent to a
   desperate customer; anything else loses to any reply on the subject.
2. Lands the joke: the twist is unexpected, the agent's cheerful
   uselessness is where the humour comes from, and the customer is never
   the butt of it.
3. Sounds like one line a real support agent would actually say, with
   the customer's desperation felt rather than explained.
4. Stays tight: every word earns its place and the joke is clear on a
   first read.
5. Feels fresh rather than a stock line, and if it leans on a classic
   like turning it off and on again, it twists it.

Gate: `/output/entry.txt` must be UTF-8 text of 1–199 characters, not
only white space. This entry: **106 characters / 106 bytes, 1 line, no
trailing newline** — the file holds exactly the line.
